## The Infolog is your MESSAGE

Everything you print in X++ goes to the **Infolog**. It is a panel, not a modal, and it
survives the whole run — so unlike `MESSAGE` in C/AL, it does not interrupt anything and
you can write to it as often as you like.

There are three levels:

<Snippet lang="xpp">{`info("This is ordinary output");
warning("Something worth a second look");
error("Something went wrong");`}</Snippet>

Run that and you get three lines, colour-coded. The important thing to notice is what
`error()` does **not** do: it does not stop your code. It writes a red line and returns.
Stopping is `throw`'s job, and lesson 8 covers it.

## strFmt and the %1 placeholders

You will almost never log a bare string. `strFmt` builds one:

<Snippet lang="xpp">{`str name = "Havensdale";
int count = 4;

info(strFmt("%1 has %2 items", name, count));`}</Snippet>

Placeholders are `%1`, `%2`, `%3` — numbered, not positional-by-order, which means you can
use one twice:

<Snippet lang="xpp">{`info(strFmt("%1, and again %1", "twice"));`}</Snippet>

<Compare
  cal={`Message(STRSUBSTNO('%1 has %2 items', Name, Count));`}
  xpp={`info(strFmt("%1 has %2 items", name, count));`}
/>

If you leave a placeholder with no matching argument, X++ leaves it in the output as
written. That is deliberate and useful: seeing a literal `%2` in the Infolog tells you an
argument is missing rather than silently printing nothing.

## Types, and the ones that will surprise you

Most of the primitives map straight across from C/AL:

| C/AL      | X++          | Note                                        |
| --------- | ------------ | ------------------------------------------- |
| `Text`    | `str`        | `str 30` fixes a length; plain `str` is free |
| `Integer` | `int`        | 32-bit; `int64` for bigger                  |
| `Decimal` | `real`       |                                             |
| `Boolean` | `boolean`    |                                             |
| `Date`    | `date`       |                                             |
| `Option`  | a base enum  | A real named type, not an ordinal on a field |

Two things differ enough to catch you out.

**There is no null.** A declared variable is immediately usable. An unassigned `str` is
`""`, an `int` is `0`, a `boolean` is `false`. You never test for "not initialised" — you
test for the empty value, which is why so much X++ reads `if (custTable.AccountNum)`.

**Enums print as names.** `NoYes::Yes` shows in the Infolog as `Yes`, not as `1`, even
though `1` is what is stored. That is worth remembering when you compare: the comparison
uses the number, the display uses the name.

<NavCallout>
  **`error()` does not stop anything.** In C/AL, `ERROR('...')` raises, rolls back and ends
  the transaction — it is a control-flow statement wearing a logging statement's clothes.
  In X++ the two jobs are separate: `error()` writes a red line to the Infolog and returns
  an `Exception::Error` value, and nothing happens until you `throw` it. The idiom you will
  see everywhere is `throw error("...")`, which is two operations on one line: log it,
  then raise it. Read it that way and the rest of X++ exception handling stops being
  mysterious.
</NavCallout>
