<Step id="intro">

## The Infolog

Everything an X++ program prints goes to the **Infolog**. It is a running list, not a
popup, so you can write to it as often as you like without interrupting anything.

There are three levels:

<Snippet lang="xpp">{`info("ordinary output");
warning("worth a second look");
error("something went wrong");`}</Snippet>

Press **Check** to run the code on the left, then open the **Infolog** tab underneath the
editor to see all three.

<Aside title="Careful">
  `error()` does **not** stop your program. It writes a red line and carries on to the next
  statement. Stopping is a separate job, done by `throw`, and the last lesson covers it.
</Aside>

</Step>

<Step id="three-levels">

## Your turn

Write one line at each level.

- an **info** reading `Starting`
- a **warning** reading `Careful`
- an **error** reading `Stopped`

Each is a function call ending in a semicolon.

</Step>

<Step id="strfmt-intro">

## Building a message

You rarely log a fixed string. `strFmt` puts values into a template:

<Snippet lang="xpp">{`str name = "Havensdale";
int count = 4;

info(strFmt("%1 has %2 items", name, count));`}</Snippet>

The placeholders are **numbered** — `%1`, `%2`, `%3` — not positional. Because they are
numbered, you can use one twice:

<Snippet lang="xpp">{`info(strFmt("%1, and again %1", "twice"));`}</Snippet>

If a placeholder has no matching argument, X++ leaves it in the output exactly as written.
That is useful: a stray `%2` on screen means you forgot an argument.

</Step>

<Step id="types">

## Variables start with a value

X++ has no null and no "not yet assigned". Declare a variable and it is immediately
usable, holding the empty value for its type:

| Type      | Starts as | Notes                                          |
| --------- | --------- | ---------------------------------------------- |
| `int`     | `0`       | 32-bit; `int64` when you need bigger           |
| `real`    | `0.00`    | Decimal                                        |
| `str`     | `""`      | `str 30` fixes a maximum length                |
| `boolean` | `false`   | Displays as `No`                               |
| `date`    | empty     | Compared and assigned like any other value     |

So you never test whether something was set — you test whether it is still empty. That is
why so much X++ reads `if (custTable.AccountNum)`.

The other type you will meet constantly is an **enum**: a named set of values, like
`NoYes` with `NoYes::No` and `NoYes::Yes`. Enums are stored as numbers but display as
their name, so `NoYes::Yes` prints as `Yes`.

</Step>
