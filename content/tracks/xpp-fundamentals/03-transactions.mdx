<Step id="explicit">

## Nothing is implicit

X++ opens no transaction for you. Every write has to say so:

<Snippet lang="xpp">{`ttsbegin;
custTable.CreditMax = 50000;
custTable.update();
ttscommit;`}</Snippet>

Leave the pair off and the write fails outright, with an error saying exactly that. It is
not the compiler being fussy — a write with no defined rollback point is a write nobody can
undo, so the platform refuses it.

`ttsbegin` opens. `ttscommit` closes and makes it durable. `ttsabort` throws the work away.

</Step>

</Step>

<Step id="nesting">

## Nesting counts, but only the outside matters

`ttsbegin` can nest. Each one raises a counter called **ttsLevel**, and each `ttscommit`
lowers it. Nothing reaches the database until the level returns to zero:

<Snippet lang="xpp">{`ttsbegin;          // ttsLevel 1
    // work
    ttsbegin;      // ttsLevel 2
        // more work
    ttscommit;     // back to 1 — nothing committed yet
ttscommit;         // back to 0 — now it is durable`}</Snippet>

That inner `ttscommit` looks like it commits. It does not; it only decrements.

This is what lets you call a routine that manages its own transaction from inside your
own, without either having to know about the other. The whole thing still lands or fails
as one unit.

</Step>

<Step id="nested-commit">

## Your turn

Insert two items inside nested transactions, then count what you have.

- at the outer level, insert `F-900` named `Outer desk`, group `FURNITURE`
- open a second level, and insert `F-901` named `Inner desk`, same group
- commit both levels
- count the `FURNITURE` items and log `Furniture items: N`

Set the fields on the buffer and call `insert()`. Between the two inserts, call `clear()`
so the second record does not inherit the first one's values.

</Step>

<Step id="abort">

## ttsabort throws everything away

Here is the part that catches people.

<Snippet lang="xpp">{`ttsbegin;
    custTable.AccountNum = "C-OUTER";
    custTable.insert();

    ttsbegin;
        custTable.clear();
        custTable.AccountNum = "C-INNER";
        custTable.insert();
    ttsabort;      // both inserts are gone`}</Snippet>

`ttsabort` does not undo one level. It discards **the entire transaction**, from whatever
depth you call it at, and puts ttsLevel straight back to zero.

<Aside title="This surprises almost everyone">
  If you picture nested transactions as a stack of savepoints you can pop one at a time,
  that picture is right for the database underneath and wrong for X++. There is one
  transaction; the nesting is only bookkeeping about when it ends.
</Aside>

An unhandled error does the same thing — it aborts the whole transaction — which is the
subject of the last lesson.

</Step>
